# Механики миниигры (поле слияний): техническое описание для анализа

Документ описывает текущую реализацию по коду репозитория (React, `src/App.tsx`, `src/utils/*`, `src/types.ts`). Цель — передать контекст другой ИИ без необходимости читать весь проект.

---

## 1. Объект состояния миниигры

- **`GameState`** (`src/types.ts`): `grid`, `energy`, `maxEnergy`, `orders`, `isFirstLaunch`, `playZone` (комната/зона, с которой открыта сессия поля).
- **`ProgressionState`**: уровень игрока `level`, XP, монеты, разблокированные зоны, апгрейды, реконструкция, коллекция — **не** хранятся внутри сетки, но влияют на награды, энергию и часть логики.

Сетка: плоский массив длины `7 × 9 = 63` (`GRID_WIDTH` / `GRID_HEIGHT` в `App.tsx`).

---

## 2. Типы клеток (`GridCell`, `CellType`)

| `cellType` | Смысл |
|------------|--------|
| `empty` | Пустая открытая клетка |
| `item` | Обычный предмет (слияние, заказы) |
| `generator` | Генератор комнаты (`item` = id генератора) |
| `lock` | Замок (открывается ключом) |
| `black` | «Туман» — закрыта, открывается каскадом при соседстве с открытой клеткой |
| `grey` | Серый блок с **скрытым** предметом (`hiddenItemId`, `hiddenItemLevel`, `hiddenItemChain`) — открывается слиянием |

Открытые для игры: `empty`, `item`, `generator` (`isOpenCellType`). Блоки: `lock`, `black`, `grey` (`isBlockedCellType`).

Дополнительные поля:

- `generatorCharges` — задаётся при появлении генератора и при миграции/апгрейдах; **в текущем коде тап по генератору не уменьшает заряды**, расходуется только **энергия** (см. §6).
- У серых клеток — только скрытые поля предмета.

## 3. Построение поля при новой сессии / сбросе сетки

Функция **`buildFreshPlayGrid(zone)`** (`App.tsx`):

1. **`generateBlockedGrid(width, height, zone)`** (`src/utils/gridUnlockHelpers.ts`):
   - Центр сетки: расстояние Чебышёва от центра `d`.
   - `d ≤ 1`: пустые `empty`.
   - `d === 2`: в основном **`grey`** с скрытым предметом через **`pickHiddenForGrey`** (цепочка комнаты + чередование с `fruit` / `sweets`, уровень от манхэттенского расстояния до центра, ограничен 1–7), иначе `black`.
   - `d > 2`: углы — **`lock`**, остальное — **`black`**.
   - В конце вызывается **`propagateBlackCellsOpen`**: все `black`, соседствующие с любой открытой (`empty`/`item`/`generator`), каскадом становятся **`empty`** (открытое поле «растёт» от стартовой дыры).

2. **`placeInitialGenerator(grid, zone)`**: в **первой** клетке с `cellType === "empty"` и `item === null` ставится генератор текущей зоны: `item = generatorItemIdForZone(zone)`, `cellType = "generator"`, `generatorCharges = INITIAL_GENERATOR_CHARGES` (5).

3. **`placeInitialKey`**: в **первой** такой же свободной пустой клетке кладётся предмет-ключ `KEY_ITEM_ID` (`cellType = "item"`).

Порядок в коде: сначала генератор, потом ключ — фактически генератор занимает первую пустую, ключ — следующую свободную пустую после этого.

При **загрузке сохранения**: сетка нормализуется, при отсутствии генератора на поле вызывается **`ensureGeneratorOnGrid`**, затем снова **`propagateBlackCellsOpen`**.

## 4. Механика слияния (два шага: выбор + drop / взаимодействие пары)

Основная логика — **`applyGridPairInteraction(from, to)`** в `App.tsx` (второй шаг после выбора ячейки; drag-drop вызывает ту же функцию).

### 4.1. Замок (`to` — `lock`)

- Источник должен быть с **открытой** клетки, не «жёстко заблокированной» в смысле кода для lock-ветки.
- На замок можно «потратить» только предмет **`KEY_ITEM_ID`**, иначе — shake.
- Нужна **энергия** `> 0`, иначе shake.
- Успех: замок → **`black`**, ключевая клетка → **`empty`**, **−1 энергия**. Краткая анимация разблокировки.

### 4.2. Серая клетка (`to` — `grey`)

- С генератора на серую — shake.
- **`tryMergeIntoGreyCell`**: на серой должен быть `hiddenItemId`; на `from` — тот же `item`, тот же уровень и цепочка, что у скрытого; генераторы и resource pickup не подходят.
- Успех: на `to` появляется **следующий уровень** той же цепочки (`ITEM_CHAINS`), `from` очищается.
- Затем **`promoteOrthogonalBlackNeighborsOfGreyToGrey`**: у **чёрных** соседей по 4 направлениям от бывшей серой позиции — если для них можно подобрать скрытый предмет — они становятся **`grey`** с новым hidden (без каскада black→empty от этого правила).
- Начисление XP за уровень **исходного** предмета на `from`, коллекция, при level up — эффекты как у обычного слияния (энергия до max при level up и т.д.).

### 4.3. Обычное слияние двух одинаковых предметов (`item` на обеих открытых клетках)

- Оба `item` не `null` и **равны**.
- Если предмет — **генератор** или **resource pickup** — shake, слияния нет.
- Иначе: по **`ITEM_CHAINS[itemDef.chain].items[itemDef.level]`** берётся **следующий** элемент цепочки (`nextItem`).
  - Если `nextItem` есть: `from` → пусто, `to` → `item` с `nextItem.id`, затем **`propagateBlackCellsOpen`** (чёрные рядом с открытыми снова могут открыться).
  - XP за **`itemDef.level`**, коллекция, квест «merge», звук, анимация merge.
  - Если следующего уровня нет (вершина цепочки) — не merge, выбор переключается на `to` (shake нет в этой ветке для «нет next»).

### 4.4. Обмен предметами (разные `item` или один пустой и т.д.)

- Если не сработали ветки выше и цель не заблокирована: **swap** содержимого через **`gridCellAfterPlacingItem`** (генератор сохраняет тип `generator` и переносит `generatorCharges` с учётом **`getGeneratorMaxCharges`**).
- После обмена снова **`propagateBlackCellsOpen`**.

## 5. Как «обновляется поле» при росте **уровня игрока** (`progState.level`)

**Сетка при level up не пересобирается автоматически.** Повышение уровня даёт:

- В **`ProgressionManager.addXp`**: разблокировка зон из таблицы **`LEVELS`** для нового уровня (в **`unlockedZones`**).
- В UI: **`triggerLevelUp`** — звук и короткая вспышка/модалка.
- При некоторых событиях при level up **энергия** подтягивается до **`maxEnergy`** (слияние, заказ, реконструкция — см. соответствующие ветки в `App.tsx`).

То есть «уровень» в прогрессии и «состояние клеток» связаны косвенно (сложность заказов, открытые комнаты), но не через полный ребилд грида.

## 6. Генераторы: как попадают на карту и как работают

### Постановка на карту

- При каждом **`buildFreshPlayGrid`**: один генератор **зоны** (`generatorItemIdForZone(zone)` из `roomMergeCatalog` / `types`: `gen_hall`, `gen_kitchen`, …).
- Старые сохранения без генератора: **`ensureGeneratorOnGrid`**.
- Соответствие комната ↔ генератор: **`ZONE_TO_GENERATOR_ID`** / **`ROOM_GENERATOR_DEFS`** (`src/roomMergeCatalog.ts`), у каждого генератора есть **`spawnsChainId`** (цепочка предметов комнаты).

### Тап по генератору (`attemptGeneratorTap`)

- Срабатывает при повторном клике по **уже выбранной** ячейке с генератором (логика `handleCellClick`).
- Если нет энергии или нет места для спавна — считается «клик по генератору обработан», без перехода к другой логике.
- **`pickEmptyCellForGeneratorSpawn`** (`src/utils/grid.ts`): сначала случайная **пустая** среди 4-соседей генератора, иначе любая пустая открытая клетка (`empty`, `item == null`, не lock/black/grey).
- Предмет: обычно **первый уровень** цепочки `spawnsChainId`; с вероятностью **`GENERATOR_RESOURCE_DROP_CHANCE`** (12%) вместо этого — монеты или энергия pickup.
- **−1 энергия** (с учётом бонусной энергии из коллекции через `registerCollectiblesBulk`), коллекция регистрируется для выпавшего id.

### Заряды `generatorCharges`

- Инициализируются и участвуют в **обмене** клеток и в **апгрейде** `gen_extra_charges` (увеличение cap и подкрутка текущих значений на поле).
- **Фактический спавн в `attemptGeneratorTap` заряды не списывает** — ограничение выдачи в рантайме идёт через **энергию** и наличие пустых клеток. В UI «генератор заблокирован» привязан к **`state.energy <= 0`** (`GameScreen.tsx`, `genBlocked`).

### Апгрейды, заявленные для миниигры

- **`energy_max`**: увеличивает `maxEnergy` (база + бонус).
- **`gen_extra_charges`**: увеличивает максимум зарядов и может добавить заряд существующим генераторам на поле.
- **`free_spawn_chance`**, **`dirty_drop_chance`**: суммируются в `getActiveBonuses`, но **в `App.tsx` при тапе по генератору `free_spawn_chance` не используется**; **`trySpawnLootOnDirtyOneClear`** из `dirtyCleanSpawn.ts` **нигде не вызывается** — механика «лута с грязи» в рантайме миниигры сейчас не подключена к полю (только утилита и тексты апгрейдов).

## 7. Заказы сессии

- На поле одновременно несколько **`Order`** (карточки с требованиями `itemId` + `count`, награда монеты/XP).
- **Сдача**: кнопка на карточке — с поля забирается **первая** подходящая клетка (`findFirstCellIndexForOrderDelivery`), предмет снимается, заказ обновляется; если заказ выполнен — удаляется, добавляется **`generateNewOrder(prog.level, gridAfterPickup, playZone)`**.
- Сложность требований зависит от **`progState.level`** в `buildRandomSessionOrder` (макс. уровень предмета, число типов в одном заказе).
- Пул цепочек для заказов: **`chainsForSessionOrders(grid, zone)`** — если на поле есть генераторы, берутся цепочки их **`spawnsChainId`**; иначе цепочка комнаты **`mergeChainIdForZone(zone)`**.

Цель сессии на поле: **`SESSION_ORDER_GOAL = 5`** выполненных заказов → флаг **`isSessionComplete`**.

---

## 8. Сессия: перемешивание, новая сессия, продолжение после «победы»

| Действие | Что происходит с полем и заказами |
|----------|-----------------------------------|
| **Перемешать** (`handleShuffleGrid`) | Новый **`buildFreshPlayGrid(playZone)`**, заказы **`createInitialOrders`**; энергия и прогресс сессии заказов **не** сбрасываются |
| **Новая сессия** при «нет ходов» (`handleSessionNewGame`) | Как shuffle + **сброс** счётчика заказов сессии и **`isSessionComplete`** |
| **Продолжить на том же поле** после 5 заказов (`handleContinueSessionSameBoard`) | **Сетка без изменений**, новые начальные заказы под текущую сетку и зону, счётчик сессии обнуляется |

---

## 9. Смена комнаты / зоны игры

При входе в миниигру с хаба **`handlePlayFromHub`**: если **`state.playZone !== activeZone`** (выбранная комната другая), строится **`buildFreshPlayGrid(activeZone)`** и **`createInitialOrders`**, выставляется **`playZone`**.

То есть смена комнаты = **новое поле** под генератор и паттерн серых блоков этой зоны.

## 10. Прочие механики на поле

- **Клик по resource pickup** (монеты/энергия на клетке): одно нажатие — предмет исчезает, начисление монет/энергии, без расхода энергии «хода» как у генератора.
- **Выбор ячейки** (`selectedCell`): первый клик по предмету выделяет; второй по другой ячейке — либо новое выделение, либо drop на пустую (сброс выделения), либо взаимодействие через пару (в т.ч. merge).
- **Drag-and-drop** (`onCellPairDrop`): тот же **`applyGridPairInteraction`**.
- **Регенерация энергии**: каждые 10 с +1 до `maxEnergy` (`ENERGY_REGEN_INTERVAL_MS`).
- **«Нет эффективных ходов»** (`isNoMoves`): вычисляется через **`hasEffectiveMoves`** (`availableMoves.ts`) — слияние/выполнимый заказ/слияние в серую/ключ к замку/клик по генератору при пустой клетке/подбор ресурса. На экране не `game` или при завершённой сессии флаг сбрасывается.
- **Коллекция**: при появлении новых id на поле после merge/spawn/order путь может вызывать **`registerCollectiblesBulk`** и награды за цепочки (энергия и т.д. по коду коллекции).
- **Реконструкция кафе**: отдельная доставка предметов со сетки (`handleReconstructionDeliver`) — не путать с заказами сессии; после доставки снова **`propagateBlackCellsOpen`**.

## 12. Краткое резюме для другой ИИ

- Поле — merge-2 **в стиле открытия тумана**: чёрные клетки открываются от соседства с пустыми/предметами/генератором; серые требуют **точного** совпадения предмета с сокровищем и дают следующий tier + локальное появление новых серых с чёрных соседей.
- **Генератор один** на свежую сетку, ставится в первую пустую после генерации препятствий; ключ — во вторую свободную пустую.
- **Слияние одинаковых** предметов на открытых клетках: пустует источник, результат в целевой, затем каскад открытия чёрных.
- **Уровень игрока** не перерисовывает сетку; меняет заказы, разблокировки в хабе и формулы наград.
- **Смена комнаты** или **shuffle** пересобирают поле и начальные заказы под `playZone` / текущую комнату.
